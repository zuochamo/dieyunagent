# 宠物（点点）

> 设置 → 宠物 → 点点。一个 128 点的桌面悬浮体，**身体即状态**：没有贴图、没有帧动画，
> 所有表现都是「改写同一批点变量」的函数。
>
> 本文只讲这一模块的口径与边界。代码分工见 `AGENTS.md` 的宠物那一行，机器索引见 `docs/CODEMAP.json`。

## 1. 文件分工（每件事只有一个地方）

| 文件 | 唯一负责 |
|---|---|
| `src/pet/settings.js` | **设置权威**：默认值、夹取、读写 `<userData>/pet/settings.json`；数字边界只在这里（生成器物理上限除外，见下） |
| `src/renderer/pet-window/pet-shapes.js` | **形态表 + 色板**（UMD 纯函数，无 DOM）：`shapePointsFor` 生成点云、`clampPointCount`；`SHAPE_KINDS` 声明 3d/2d |
| `src/renderer/pet-window/pet-cat-gait.js` | **猫的步态**（UMD 纯函数）：四拍对角步行的相位、支撑/摆动占空比、躯干起伏、尾巴慢摆，输出逐点偏移 |
| `src/renderer/pet-window/pet.js` | 悬浮窗页面：128 组变量 + 弹簧 + 手写透视投影 + morph/呼吸/涟漪/暗下去；渲染帧率与穿透判定 |
| `src/main/pet-window.js` | **窗口生命周期唯一实现**：透明置顶、拖动绝对定位、命中式点击穿透、显示器变化后夹回工作区 |
| `src/main/ipc/pet.js` | 只做传输（`pet:get-settings` / `set-settings` / `set-enabled` / `ready` / `drag-*` / `mouse-mode` / `state`） |
| `src/renderer/pet-window/preload.js` | 悬浮窗专用小桥（**不共用主窗口 preload**，少带整个 `diecloud.*` 攻击面） |
| `src/renderer/renderer-pet.js` | 设置页 UI（滑杆防抖提交，多次改动合并成一次 patch） |
| `src/alive/pet-tools.js` | **身体工具的语义**：参数白名单（`normalizePetSet` / `normalizePetAct`）与执行（`runPetSet` / `runPetAct`）。**心跳轮与聊天轮共用这一份**；schema 在 `src/agent/catalog/pet.js`（工具 schema 单一来源） |

## 2. 设置字段（`pet/settings.json`）

| 键 | 含义 | 夹取 / 默认 |
|---|---|---|
| `enabled` | 是否显示（**预装默认关**） | 只有显式 `true` 算开；缺键 / `'no'` / `0` 一律关 |
| `aliveBind` | 绑定生命感（体征驱动 + 心跳轮的它可调身体） | 默认 `true`，只有显式 `false` 算关 |
| `count` | 点数量 | 用户区间 64–512（生成器物理下限 16 / 上限 512，在 `pet-shapes`） |
| `size` | 窗口边长倍率（1.0 = 280px） | 0.6–1.8，默认 0.75（= 210px） |
| `motion` | 动效强度（含步态幅度） | 0–2，默认 1；**0 = 完全静止** |
| `dotScale` | 单点半径倍率 | 0.5–2，默认 0.5 |
| `color` | 点色（`pet-shapes.COLORS` 的 id） | 默认 `white` |
| `x` / `y` | 悬浮窗左上角（DIP） | `null` = 未拖过，用主屏工作区右下角默认位 |

`pet:apply` 下发的**只有这些**；页面自己在内存里另有一份 `settings.shape`（当前形态），
不放磁盘、也不是设置（见 §3）。

## 3. 形态：只有运行状态，没有设置项

- **没有「形态偏好」设置**（曾有过 `shapeMode` = auto/sphere/cat，已整体删除）：形态永远由它自己决定，
  按闲逛日程在球/猫/鱼之间换（`AUTO_SHAPES` + `SPHERE_STAY_MS` / `CAT_STAY_MS`，写死区间）。
  用户要的就是「它可以一直变」，钉死一个形态的需求不存在。
- 当前形态（球 / 猫 / 问号是瞬时姿势）只有悬浮窗知道。它每次变化都经 `pet:state` 回报给 Main，
  心跳轮的事实块 `bodyLine` 报的是**页面回报的当前形态**——不是存档值（存档里根本没有形态）。
- 老存档里若残留 `shapeMode` / `shape` 字段，**一律不读**：删掉的设置项就当没看见，不写迁移链。
- 模型想让它是某个形态，用 `pet_act({ effect: 'shape', shape: 'cat' })`：这是**动作**（现在就换，之后照旧自己变），
  不写设置、也不是偏好。合法形态取自 `pet-shapes.SHAPE_IDS`（schema 的 enum 由它生成）。

## 4. 猫的步态（`pet-cat-gait.js`）

- **四拍对角步行**，落足顺序 **右前 → 左后 → 左前 → 右后**，每条腿相差 1/4 拍；
  一个周期 ≈ 2.6s（1.5 步/秒）。四条腿来自侧视描边上前后各两笔（远侧 + 近侧）。
- **支撑相 66% / 摆动相 34%**：支撑相脚踩住、腿相对身体匀速后扫；摆动相收回 + `sin` 弧线抬脚。
  这就是「看起来在走」而不是「脚在溜冰」的关键。
- 位移用**按离髋深度线性**的连续场，不用绕枢轴刚体旋转：轮廓是描边，旋转会在腹线处撕开一道口子；
  线性场里髋不动、脚掌满幅，脚的高度只由抬脚量决定（支撑相不会被抬离地面）。
- 同一区间里远近两条腿的位移在分界处交叉淡入淡出；远侧那条**压暗 + 变细**（`FAR_SHADE`），
  四条腿才分得出前后。
- 躯干每周期起伏两次（头只吃 30% + 一点自己的点头，猫走路头是稳的），背线有行波，尾巴绕尾根慢摆、
  沿长度有延迟（**站着也在动**）。
- 动效强度 0 时整套步态归零（腿与躯干完全静止），只有尾巴还摆。

改走路只改这一个文件；`test/unit/pet-gait.test.cjs` 会验：分区无孤儿点、腹线不被拽走、
支撑相不抬脚且单调后扫、四拍顺序、站位静止、步幅有界、同一部位位移场连续（描边不撕裂）。

## 5. 交互与窗口

- **命中式点击穿透**：整块矩形默认穿透；页面做「指针是否压在点身上」的判定，压到了才关穿透。
  命中容差下限跟着身体半径走（`R * 0.14`），并且**进来快、出去稳**（放行用 1.35× 容差 + 90ms 延迟），
  否则在点云边缘每几像素就会切一次穿透（每次都是一次 IPC + 系统调用）。
- `focusable: false` + 首次 `showInactive()`：**点它不抢你正在打的字**。这是桌面宠物的底线。
- 拖动报**指针屏幕绝对坐标**，Main 记抓取偏移后 `setPosition`：窗口追指针，没有增量反馈回路。
  拖动是一条状态机，三条不变量（`test/unit/pet-window-page.test.cjs` 的 `pet window drag` 守着）：
  1. **「能拖」的区域必须等于「光标显示 grab」的区域**：窗口已是可交互态（`overBody`）时，按在任何位置
     都能开始拖。以前按下又退回严格命中 —— 指针停在 1–1.35 环带里（光标是 grab）或点云漂走时按下去
     什么都不发生；猫/鱼是描边形态、中间是空的，于是表现成「抓不住 / 拖不动」。
  2. **mouseup 会丢**（`focusable:false` 的无边框窗口，指针快速离开或窗口被夹在屏幕边缘时）：
     `mousemove` 用 `buttons === 0` 兜底收尾。没有这条，`press` 常驻，之后既不再判命中、
     也不再放行穿透 —— 窗口永久挡住鼠标。
  3. **Main 的抓取偏移丢了不能静默丢弃移动**（`dragStart` 没拿到窗口 / `getBounds` 抛错 / 窗口刚重建）：
     `dragMoveTo` 用「指针 − 当前左上角」现补一份（新位置 = 当前位置，不跳），拖动照常继续。
     静默 return 的表现正是「页面在拖、窗口一动不动」。
- 单击只清拖动状态、不写盘（`dragEnd({ moved:false })`）；只有真拖动过才落盘位置。
- 跨屏拖动时窗口中心落在**两台显示区之间的缝**里（混合 DPI / 不同分辨率的排列下系统报出来的
  显示区之间确实有空隙）→ 夹进**最近**那台显示器的工作区，不回退主屏。回退主屏 = 宠物突然跳回主屏，
  用户看到的就是「拖不过去 / 位置卡死」。
- 显示器增删 / 分辨率变化 → 窗口夹回它中心所在显示器的工作区并落盘（否则拔屏后它停在不存在的屏幕上）。
- 渲染 `rAF` 上限 ~30fps，`document.hidden` 时只转空循环不推进状态。
  `backgroundThrottling: false` 保留（被遮挡时也要保持节律），节律本身由页面控。

## 6. 与生命感的接口

- `aliveBind` 打开 且 `enabled` 打开时，Main 才把体征与事件转给悬浮窗（`pet:alive`）。
- 体征映射：疲劳 → 下垂 + 迟缓（`droop`）、相位 `ALERT` → 活跃（`excite`）、负载 → 逐点噪声更大（`load`）、
  相位 `COMPRESS`/`LOW` → 收拢（`huddle`）。
- 事件映射在 `pet.js` 的 `ALIVE_EVENT_FX`（WAKE→涟漪、ACT→pulse、DEFER→问号、REFUSE→暗下去、SPEAK→光波）。
  `dim` 是一个会自己衰减的乘子（乘进最终 alpha 与半径）——**只压 `glow` 是看不见的**（glow 平时是 0）。
- 两件工具在**两个轮次**都能用，语义是同一份（`alive/pet-tools.js`）：
  - **聊天轮**（用户在场）：常驻在桌面版工具表里 —— 用户说「点点改成 256 个点 / 换个形态」时，
    模型直接调参数，**不要去改源码**（2026-11-24 现场：它们只进心跳轮，于是模型去改了 `settings.js`）；
  - **心跳轮**（绑定生命感后醒来）：`main/alive-boot.js` 的 `extraTools` + `preTool` 追加这两件，
    与档位白名单无关（它自己的工具不经过工具桥）。
- 宠物没显示 / 这台机器没有宠物时，执行端回**结构化错误**（`PET_DISABLED` / `PET_UNAVAILABLE`），
  不是「工具不存在」—— 与 `peer_*` 的 `PEER_UNAVAILABLE` 同一取舍：藏在工具表外只会让它去改源码。
- 参数级改的是设置（用户滑杆同一份）；效果级（涟漪/挤压/问号/暗下去/聚神/换形态）不留持久状态。
  逐点写 128 个浮点要几百 token 且模型写不稳 —— 所以只有动词，没有原始写接口。
  显隐、屏幕位置与「钉死形态」不归它管。

## 7. 负向清单（别这么做）

- 别在 Main / 设置页另写一份色值或形态枚举 —— `pet-shapes` 是唯一来源。
- 别绕过 `settings.js` 直接改 `pet/settings.json` 的合并逻辑（patch 只有一个写入口）。
- 别在渲染端 `new BrowserWindow` 或写窗口定位（生命周期只在 Main）。
- 别让悬浮窗抢焦点（`showInactive` / `focusable:false` 是底线）。
- 别给 128 点开原始写接口（动词优先，见 §6）。
- 别在 headless 装配它（没有 GUI）。
- 别在 `pet.js` 里再写一份腿摆或步态常量 —— 全在 `pet-cat-gait.js`。
- 别让拖动只靠 `mouseup` 收尾（`focusable:false` 的窗口会丢它），也别在按下时用比「进入」更严的
  命中容差 —— 这两条都会表现成「宠物抓不住 / 拖不动 / 位置卡死」，见 §5。
- 别在多屏夹取里回退主屏（窗口中心落进显示区之间的缝时会跳回主屏），要取最近的那台。
- 别为「它自己变过的形态」加持久化：每次形态变化都写盘是没必要的 churn，也没人会去核对。
- 别再把 `pet_set` / `pet_act` 只挂回心跳轮：聊天轮里缺这两件，模型就会去改 `src/pet/settings.js` 的源码
  （它把「运行时设置」当成「代码缺陷」来修）。schema 归 `agent/catalog/pet.js`，执行归 `alive/pet-tools.js`。
- 别把「钉死形态」做成设置项（用户明确要求它可以一直自己变）。要改节奏就改 `AUTO_SHAPES` 的停留区间。
