## 2. 分层策略与判定口径

### 2.1 六层（由快到慢，前层失败不阻塞后层，但结论要合并）

| 层 | 名字 | 作用 | 失败含义 |
|---|---|---|---|
| L0 | 前置闸门 | 确认工具链/sidecar/无残留进程 | 环境问题，先修环境再谈结果 |
| L1 | 静态与契约 | `check:js` / `lint:agent` / 契约生成器 `--check` | 编译级错误、文档/契约漂移（**必须 0 容忍**） |
| L2 | 单元（vitest） | 230 个文件，快、定位准 | 逻辑回归，最容易定位到函数 |
| L3 | 模块 smoke | 每模块的 `scripts/test-*.cjs`（起假 gateway / 临时项目） | 模块内集成回归 |
| L4 | 跨语言链路 | Node ↔ Rust sidecar（`core-bridge` / `rust-*-smoke` / `local-gateway-smoke`） | 协议/契约层回归，最难查 |
| L5 | 产物与分发 | `verify:*`（asar / remote-pack / mcp-bundled / headless tgz·deb·apt） | 打包/分发回归（本机部分无产物，见 §9） |
| L6 | 行为观测 | 日志、时间戳、界面手工点检 | 只能证伪不能全证，报告里单列 |

### 2.2 判定四分法（每个 FAIL 必须落到一格）

| 分类 | 判据 | 处置 |
|---|---|---|
| **新回归** | 失败签名不在 §7 基线里；或基线项通过数变少；或出现新 FAIL 名 | 单独立案：现象 → 根因 → 影响面 → 修法建议 |
| **已知基线** | 签名（错误信息 + 通过项数量）与 §7 完全一致 | 标「非回归」，附基线编号 |
| **环境前提** | 缺真实远端 / 缺真实 LLM 配置 / 宿主注入变量 / 缺产物 | 标「未覆盖 + 原因 + 补齐条件」 |
| **预算超时** | 命中 runner 的 10 分钟超时、无断言失败 | 重跑一次并放宽 `--timeout`，仍超时则记为预算问题 |
