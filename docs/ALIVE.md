# 生命感（`src/alive/`）

> 一句话：**这不是生命模式，是生命感。** 它让 agent 在两次对话之间仍有内部状态、会自己醒、能拒绝，
> 但它**不会死**、**没有损耗**、**不隔离记忆**。

| 项 | 内容 |
|---|---|
| 定位 | 拟态（研究性副项目，不进生产承诺） |
| 入口 | 设置 → 生命（一个总开关） |
| 数字来源 | `src/agent/agent-limits.js` 的 `alive*` 段（唯一一处，不进设置页） |
| 状态 | `<userData>/alive/state.json` + `events.jsonl` + `settings.json` |
| 验收 | `npm run test:alive`（52 项，注入时钟模拟 30 天，不挂机） |

---

## 1. 与原 `--alive` 设计的差别（先说清楚砍了什么）

原设计（`F:\dieyunagent-alive-DEVSPEC.md`）的承重墙是 **C4 必死**：预算耗尽即死亡、记忆不可逆衰减、
遗物有损继承、`incarnation` 不可复制。本实现**明确不做**这些，只保留"看起来像活着"的那一层。

| 原设计 | 本实现 | 为什么砍 |
|---|---|---|
| 预算 = 寿命，`EXHAUST` 主路径 | 无预算、无死亡 | 会死的东西必须回答"死了以后呢"，而重生/遗物/谱系会带来一条完整的维护链 |
| 记忆 `FULL→COARSE→GONE` 单向 | 不做，记忆就是主库那套 | 共享记忆是"看着像生命"的前提（它记得你们聊过什么），而不是敌人 |
| `seed_artifact` 有损遗物 | 不做 | 没有死亡就不需要遗物 |
| 独立数据库、独立 API Key、网络命名空间 | 不做 | 同一份 userData、同一份模型配置 |
| `incarnation` 绑定、拒绝启动 | 不做 | 没有"这一代"，只有"这个功能开没开" |
| `sealed` 区（理由不进日志） | **保留**（`state.intents` 本机私有） | 这一条决定了它会不会"为观众活" |

保留了原设计的四条里最不痛的三条：**基线活动（C1）、自发唤醒（C2）、可拒绝（C5）**，
另外把"相位惯性（C7 的工程化）"与"性格 = 阈值轨迹"一起留下。

## 2. 一次心跳做什么

```
每 300s（aliveTickIntervalMs）：

1) 漂移     T += α·Σ(未闭合项张力)·Δt + θ·(T_回复中心 − T)·Δt − 0.05·关闭数·Δt + ε·√Δt·N(0,1)
            F += (本轮 token/1000)·k − 静息·Δt + ε_F·√Δt·N(0,1)
2) 消退     很久没被声明的未闭合项按 48h 时间常数淡掉（淡到 <1 直接清）
3) 阈值     W += (μ·(基线 − 拒绝率) + ν·(疲劳/100 − 0.5))·Δt(小时)，夹在 40..80
4) 相位     target(load, fatigue) → 连续 k 个 tick 才切换（ALERT/LOW/SETTLE/COMPRESS）
            **相位只由 load 与 fatigue 决定，没有昼夜输入** —— COMPRESS 是"高疲劳压缩"，
            不是"夜里重组"（代码里没有任何按小时/按星期判断的分支）
5) 唤醒     T ≥ W ∧ 非 COMPRESS ∧ 距上次 ≥ 10min ∧ 今日 < 100 次
            → 记 WAKE（trigger=internal，带当时的 load），跑一轮「后台心跳轮」
6) 落盘     state.json 原子写；事件追加进 events.jsonl
```

> `load` 高（有人在用）**不阻止**唤醒：拟态的节律不该由"你正好在打字"决定。
> 但这件事必须看得见 —— `WAKE.load` 记下当时忙不忙，页面把 `load ≥ 0.35` 的那次标成「（你正在用）」。

### 两个 token 口径（别混）

| 量 | 口径 | 谁在用 | 为什么 |
|---|---|---|---|
| **load**（相位） | **全进程**滑窗用量（用户聊天也算忙） | `targetPhase` → ALERT / COMPRESS | "这台机器现在忙不忙" |
| **疲劳 F** | **只数唤醒轮自己**用掉的 token（`runtime.js` 只在 `wakeInFlight` 期间收） | 压缩相位门限 + 阈值漂移 | "它自己累了没有" |

疲劳系数 `aliveFatiguePerKToken = 0.5`：一次唤醒轮（≈40k token）≈ +20 疲劳 ≈ 1 小时静息回补。
**曾经的坑**（issue/2026-11-10）：系数取 4 + 全进程旁听 → 用户在主对话里聊 2.5 万 token
就把它的疲劳打满 100，于是它长期停在 COMPRESS 相位、永远不醒，而页面上只看到"疲劳 100"。
结论：**别人的账不能记在它头上**，这一条写进断言（`scripts/test-alive.cjs` 的 G 组）。

### 事件流写什么（`events.jsonl`）

| kind | 何时 | 关键字段 |
|---|---|---|
| `BIRTH` | 第一次出生 | phase / threshold |
| `PHASE` | 相位真的切换 | from / to / load |
| `WAKE` | 张力越线要醒 | tension / threshold / phase / **load**（当时这台机器忙不忙 = 是不是在你说话时醒的） |
| `WAKE_END` | 醒来那一轮收尾 | phase / tension / **tokens**（这一轮烧了多少）/ **durationMs** |
| `WAKE_NO_DECISION` | 醒来却没调 `alive_decide` | tokens / durationMs（这一轮白醒了，张力继续累积） |
| `WAKE_SKIPPED` / `WAKE_ERROR` | 没跑 / 跑失败 | reason 或 message |
| `DECISION` | 模型通过 `alive_decide` 表态 | decision / loopId / **closed**（这次 REFUSE 有没有真关掉一条） |
| `SPEAK` / `LISTEN` | 每次动嘴/动耳（含被拒、含失败） | ok / chars / seconds / errorCode |
| `EYE` | 每次睁眼（`camera_look` / `desktop_camera_look` 返回后） | ok / device / width×height / errorCode |

**为什么不逐跳写 `TICK`**：心跳 288 次/天，`events.jsonl` 上限 2000 行（超了裁一半）→ 4 天就会把
`WAKE` / `DECISION` 挤干净，决策日志直接不可读。心跳的账由 `state.json` 的 `tickCount` /
`lastTickAt` 记，页面把这两项显示出来（"第 N 次心跳（上次 HH:MM）"），要审计对得上就够了。

**成本也要能回答**：`WAKE_END.tokens` / `durationMs` 与 `state.lastWakeTokens` /
`lastWakeDurationMs`、`state.totalTokens` 都在面板上（"累计唤醒 X token · 上次醒来 Y token / Z s"）。
它花的是同一份账单，"心跳贵不贵"不该只能翻 state.json 才知道。

**T 的回复中心会随静默时长上升**（`aliveTensionIdleRampPerHour`）：闲久了会"坐不住"，
所以一个**没有任何未闭合事项的新实例也会在几小时后自己醒一次**。没有这一项，拟态就失效了
（它会永远停在 20 分，什么也不发生）。

> **标定（2026-11-11 实测）**：初版数字（W=60 / 宽限 1h / 每小时 +6 / 回复 0.35）跑出来是
> **静默 11.7 小时**才第一次自发醒（200 次蒙特卡洛，无未闭合项），和上面那句"几小时"对不上，
> 用户侧看起来就是"生命模式没动静"。现取值 W=40（下限）/ 宽限 0.25h / 每小时 +20 / 回复 0.6
> → **中位 2.4 小时**第一次醒，之后每醒一次静默钟重走一遍。
> 成本口径（2026-11-12 两次抬高后）：一次唤醒轮实测 2–7 万 token；`aliveDailyTokenBudget` 已从
> 40 万抬到 **1 亿**，**这道闸实际上被打开了**（100 次/天 × 最多 7 万 ≈ 700 万，只占 7%）。
> 现在真正栓住节律的是 **`aliveWakeMaxPerDay`（100 次/天）** 与 **疲劳**（每次唤醒 +20，
> 静息 20/h → 连续 3–5 次进 COMPRESS 相位，那相位不唤醒）。额度留着只防上游异常（一次请求叠几十万 token）。

## 3. 决策权在模型

后台心跳轮与用户轮走**同一份** `runMainTurn`，只差三件事：

| 差别 | 实现 |
|---|---|
| 不产出面向用户的内容、不沉淀长期记忆 | `internal: true` |
| 默认只读 | `toolScope.readOnly` → `tool-gate` 的 `read-only-scope` 关卡（复用 `isWriteTool`） |
| 多一个工具 + 一个合成状态块 | `alive_decide` + `[系统] 生命体征` 块 |

```
alive_decide { decision: ACT | DEFER | REFUSE, intent, loopId?, loops? }
```

- **ACT**：继续这一轮，用普通（只读）工具做点事
- **DEFER**：判断现在不合适，本轮结束，张力继续累积
- **REFUSE**：决定某件未闭合的事不值得做，把它从清单里关掉（张力清零，决策有记录）。
  **必须带 `loopId`**；空手的 REFUSE 等于 DEFER，且**不计入拒绝次数**——否则"嘴上拒绝、
  什么都没关"会把拒绝率抬上去，「可疑顺从」告警就失真了（`DECISION` 事件里的 `closed` 照实写）。
- **`done: [loopId]`（完成收口）**：ACT（或任何决定）里带它，把**做完了**的条目关掉。
  `DECISION.done` 记条数，与 REFUSE 的 `closed` **分开**——一个是"我做完了"，一个是"我不做"。

> **为什么必须有 `done`**：在有它之前，唯一能关掉条目的动作是 REFUSE，于是动机回路是倒的 ——
> **拒绝解渴、做事不解渴**。一条未闭合项的张力是 `weight × 25`（基准），每跳贡献约 +8.75/小时；
> 关掉它，这份增益立刻消失（`totalLoopTension` 少一条），这才是"做完会松一口气"的机制。
> 没有它，它只能背着永远做不完的清单，直到拒绝或 48 小时自然衰减。

`intent`（为什么）只写进 `state.intents`：**不进事件流、不进 IPC、不进页面**。
设置页能看到"它拒绝了 4 次"，看不到那 4 个理由。理由一旦公开，它就会开始为观众活。

未闭合事项（`open_loop`）由模型在 `alive_decide.loops` 里**自己声明**，
代码不猜"这轮算不算没做完"——那必然落到关键词匹配上（AGENTS 原则 3 明令禁止）。

### 「有没有人在场」是事实，不是代码的结论

状态块的最后一行以前**无条件**写「这台机器上没有人在等你回话」。后果是：它每次醒来都只
自言自语，永远不会开口——你等不到它说话，不是它不肯，是代码替它判了"没人在"。

现在分两行：**一行报事实，一行给许可**，任何 `load` 下都不再宣布"没人在"。

| `load` | 递给模型的事实 |
|---|---|
| > 0 | 最近 5 分钟这台机器上有对话活动（load X）：可能有人就在旁边 |
| = 0 / 未知 | 最近 5 分钟这台机器上没有对话活动（load 0）：没有人正在跟模型说话 |

许可那行是固定的：**画面里有没有人在、有没有该做的事，你自己看、自己判断；真有话说就出声
（`alive_speak`），说给在场的人听，不是汇报，也不是进度条。**

> 为什么 2026-11-12 又改一次：`load` 只数"这个 App 里有没有人在跟模型说话"，
> 你安静坐在摄像头前属于 `load = 0`。旧写法在 `load=0` 时直接宣布「没有人在等你回话：
> 不要写给人看的汇报」——于是它**拿着照片里明明有人的画面**，照着这行字闭嘴。
> 屋里有没有人是它看见的，不该由代码替它下结论（与"不猜意图"同一条原则）。

仍受 `voicePolicy`（`voiceSpontaneous` + 每日 100 次 + 两次间隔 ≥20 分钟）约束；
**它不会往你的对话线里写消息** —— 那是"接管对话"，设计上明确不做。

### 想跟它说话：去它醒来的那个会话

唤醒轮是**普通 `runMainTurn`**，会话 id 存在 `alive/settings.json#sessionId`、标题固定
「生命体征（后台心跳）」。它会读这个会话最近 120 条消息，所以：

- **在那个会话里打字** = 跟它同一个账本说话，下一次唤醒它能看到你说过什么（最直接的"跟它说话"）；
- 在任何别的会话里说话，对话的是**同一个 agent**（同一份长期记忆、同一套人格），
  但那句话不会进入唤醒轮的上下文，也不会让它"知道你在等它"——除了记忆里恰好被召回；
- 它醒来的产出（自述 / 决策 / 抽屉）留在那个会话与「生命」面板里，不会弹到你的对话中；
- **那条会话被归档了怎么办**（2026-11-13 修）：归档是用户的决定，代码不改 `archived` 位；
  但唤醒轮下一轮会发现绑定的会话已归档，**另开一条新的**并把 id 写回
  `alive/settings.json#sessionId` —— 否则它照常跑、正文照常落库，而侧栏翻不到那条会话，
  等于把记录丢进看不见的地方（当时的实测症状：用户归档后找不到它在哪儿说话）。
  换会话不丢连续性的三件东西是抽屉（`alive/workspace/note.md`）、未闭合项与体征（`state.json`）。

## 4. 设置页有什么 / 没有什么

| 有 | 没有 |
|---|---|
| 总开关（开 = 起心跳；关 = **停表**，体征保留） | 暂停 / 恢复 / 回滚 / 快照 / 克隆 |
| **它用哪个模型**：唤醒轮绑定的模型路由（空 = 跟随默认；选项与「定时计划」同一份枚举） | 给它单独配 API Key / 端点（那是模型设置的事） |
| **它醒来能做什么**：`read` / `write` / `exec` 三档（界面上写作 **1 / 2 / 3 级**，文案只在 `renderer-alive.js#ALIVE_POWER_TIERS` 一处）+ 一个根目录 + 每轮次数上限（默认 `read`） | 内核级沙箱 / egress 限制（沙箱是策略层，见 `docs/SANDBOX.md`） |
| 只读体征：相位、张力/阈值、疲劳、未闭合条数、今日唤醒、决策计数、**今日 token / 额度** | 死期 / 剩余天数 / 倒计时（没有死亡，也就不该有） |
| **体征趋势曲线**（最近 7 天：张力 + 疲劳 + 底部相位色条；数据在 `alive/history.jsonl`） | 导出 / 编辑历史 / 手动打点 |
| 决策与感官日志：`时间 · 事件 · 细节`；抽屉（`note.md` 原文）与它是「日志」页里**两组横向标签**（2026-11-15 从「生命」页搬进来） | 「为什么」那一列（`intent` 本机私有） |
| 「重新开始」（清空体征，重开时重新出生） | `λ / ε / W / fuse` 任何性格参数旋钮 |
| **设定**（拟态 → 设定：**一个文本框**，内容随意——人生目标 / 遇到人怎么反应 / 想聊什么…，整段只进后台心跳轮的状态块） | 人格化皮肤的其它部分（头像 / 情绪标签 / 预置人格包）—— 设定是你写的一段字，不是可选项里的一个 |
| 可疑顺从提示（醒了多次却一次没拒绝） | 人格化皮肤（名字 / 头像 / 语气 / 情绪标签） |
| **成本护栏**：每日 token 额度用完就停到明天（数字在 `agent-limits`，页面只读） | 额度旋钮 / 退避表 / 分时段配额 |

**侧栏还有一个「生命」页**（`data-side-tab="alive"`）：与这一页**同一份渲染、同一份 IPC**，
只是不必打开设置就能看到"它在你不看时做了什么"（概览 / 曲线 / 事件与抽屉两组横向标签），
rail 上那个心跳图标**跟别的 rail 图标完全一样**：同色、不动（2026-11-13 按用户要求先删律动、
再删相位色）。相位只写在它的工具提示里，曲线在「生命」页里看。
理由与实现见 `docs/ALIVE-VISIBILITY-PLAN.md`。

开关语义要说死：**关掉不是暂停**。体征留着，重新打开会接着上一次的心跳继续走；
想从零开始用「重新开始」。

### 设定（拟态 → 设定）：**一个框**，写什么随你

「生命」那一页回答**它现在怎么样**（体征 / 感官 / 权力，全是数字和开关）；
「设定」这一页只是**一个文本框**：你随手写的整段话，存 `alive/settings.json` 的 `setup`，
`runtime.js` **每次唤醒现读**，交给 `decide.renderStateBlock` **排在一切事实之前**
（先知道"我该在意什么"，再看外面发生了什么）。

- 页面**不拆字段、不加说明文案、不显示字数计数器** —— 写人生目标、遇到人怎么反应、想聊什么，
  并列着写就行；代码只按原文照贴，不解析、不拆成任务、不猜哪句重要。
- 上限 `aliveSetupMaxChars`（2000 字，读写两侧都夹）：这是每轮唤醒都要付的 prompt 成本；
  真被截断时，页面保存后才报一句「超出上限的部分已截掉」。

**为什么这一段能治"一直 DEFER"**：它每次醒来的原始处境是「空张力 + 空清单」——
没有一件"属于它自己的事"，`alive_decide` 的答案就只能是 DEFER（不是懒，是没有方向）。
所以有设定时，状态块会把"设定 → 这一小步"这条换算说出来：

- 设定写的是方向：每次醒来问「这一小步能是什么」，把那一小步写成 `loops`，做完用 `done` 收口；
- 设定里说了要开口的事（遇到人打招呼、偶尔聊两句）就按它办 —— 没说话只说明还没决定说；
- DEFER **要说得出口**（为什么现在不合适、什么时候合适），说不出就别 DEFER，哪怕只做一小步。

两条刻意不做的事：

1. **不替它编设定**：没写就是空的，代码只把"你现在缺的正是方向"这个事实说出来。
   拿代码给它写人生，比它一直 DEFER 更假。
2. **不进对话系统提示**：这段只进后台心跳轮的状态块 —— 对话那边的规则是另一份单一来源
   （`agent-system-prompt.js`），不能被一个设置页的文本框改写。
   你也别指望它带着这段设定跟你聊天：设定是**这条命自己的底稿**，不是人格皮肤。

## 5. 感官（A 抽屉 / B 眼睛 / C 嘴与耳）

三个开关都在「设置 → 拟态 → 生命」页，**默认只开抽屉，眼睛与嘴默认关**。

| 开关 | 默认 | 它能做什么 | 硬边界 | 还需要什么 |
|---|---|---|---|---|
| **抽屉** `senses.drawer` | **开** | `alive_note`：往自己的 `alive/workspace/note.md` 追加一行；`alive_read_note`：**读回**（没有路径参数，只能读这一个文件） | 只读/只写自己目录、只追加、单条 ≤600 字、整体 ≤32KB（超了留尾部） | 无（目录在**启用那一刻**建好） |
| **眼睛** `senses.eyes` | 关 | `camera_look` / `desktop_camera_look`：拍一张现实画面 | 不落盘；画面进视觉通道后即弃；**不留缩略图**（见下） | **还要在「设置 → 权限」把摄像头打开**（两道锁）；面板会显示"待授权" |
| **嘴与耳** `senses.voice` | 关 | `alive_speak`：说一句（≤300 字）；`alive_listen`：听 1–15 秒 | 音频**不落盘**（临时文件用完即删）；没有"一直听着"的形态 | 语音槽位配置 + `ffmpeg`/`ffplay` + 麦克风设备（页面下拉选，`DIEYUN_MIC_DEVICE` 只作高级覆盖） |
| **主动开口** `voiceSpontaneous` | 关 | 允许它在**没人说话时**出声 / 开麦 | 每日上限 `aliveVoiceMaxPerDay`、两次间隔 `aliveVoiceMinIntervalMs`；被拒也留 `SPEAK`/`LISTEN` 事件 | 勾了「嘴与耳」才有意义 |
| **醒来时先看一眼·摄像头** `wakeLookCamera` | 关 | 唤醒轮**开始前**抓本机摄像头一帧，作为这一轮的输入 | 画面**不落盘**；每次唤醒最多一帧；成败都写 `EYE` 事件并如实写进状态块 | `senses.eyes` + `permissions.desktopCamera` + 有 ffmpeg + 文本模型标成「全模态」 |
| **醒来时先看一眼·屏幕** `wakeLookScreen` | 关 | 唤醒轮开始前截主屏一张 | 同上（屏幕内容更敏感：会随这一轮发给模型） | `permissions.osControl`（与 `computer` 工具同一份授权）+ 全模态模型 |

### 它说了什么，在哪儿看得到

出声是**说给在场的人听的**，而人可能不在、可能没听清 —— 所以「说了什么」必须留成可回看的文字。
**展示 ≠ 接管对话线**：这些文字**不写进你的会话账本、不进模型上下文、不参与压缩**。

| 在哪 | 长什么样 | 数据来源 |
|---|---|---|
| 主窗口（气泡区上方一行） | 出声了就是 `它说（08:12）：…`；没出声的那些唤醒轮显示 `它醒来写了（06:07）：…` + 「日志」/「✕」；✕ 只收起这一条，下次它再动起来会重新出现 | `state.json` 的 `lastVoiceText`/`lastVoiceAt` 与 `lastWakeText`/`lastWakeTextAt`（`alive:badge` 带回，30s 轮询；两者取**更新的那条**） |
| 设置 → **拟态 → 日志** | 逐条：`08:12 · 说：「…」`（历史事件，失败也写原因） | `events.jsonl` 的 `SPEAK.text` |
| 侧栏「生命」页 | 同一条事件流的最近若干条 | 同上 |

只保留最近一条（`state`）/ 每条最多 `aliveVoiceTextMaxChars` 字（事件）。`alive_listen` 不动这条 ——
只听不说不该把上一句擦掉。

> **「它醒来写了」为什么必须有**（2026-11-13 加）：唤醒轮是 `internal: true`，正文只落进它自己的
> 会话库 —— 它一夜写了四万多字节，人回到主窗口什么也看不见，"它在你不看时做了什么"只能靠翻日志。
> 现在每轮收尾把正文**压成一行**（`aliveWakeTextMaxChars`）留在 `state.lastWakeText`，
> 主窗口那行在没有更新的一句话时显示它。仍然是同一套语义：**展示，不进会话账本、不进模型上下文**；
> 空正文（DEFER 那种没写东西的一轮）不覆盖上一行。

> **与负向清单 #4 不冲突**：私有的是 `intent`（"为什么这么决定"）。它**说出口的那句话**是事实、
> 发生在你面前，本来就得能被听见、被回看；把事实藏起来只会让人以为它什么都没做。

### 醒来时它到底看到什么（`alive-boot.js#collectFacts` 是唯一装配点）

唤醒轮不是"凭空醒来"：跑这一轮**之前**会装两类事实，然后一次性交给 `decide.renderStateBlock`。

| 事实 | 来源 | 上限 | 成本 |
|---|---|---|---|
| **最近这台机器上在做什么** | `memory.sessions_list` + `memory.messages_recent`（`src/alive/recap.js`） | 时间窗 `aliveRecapWindowHours`、最多 `aliveRecapSessions` 个会话、每句 `aliveRecapTailChars`、整块 `aliveRecapMaxChars` | +1–2k token |
| **最后一次听到人说话** | 同一次取数里的最后一条 `role: user`（合成消息按前缀排除） | 同上 | 含在上面 |
| **未收尾的目标型计划** | `plans/store.js#list`（`trigger==='goal'` 且 `outcome` 空） | 最多 `aliveRecapPlans` 条，每条目标/首个检查/上次结果 | 含在上面 |
| **醒来时先看一眼** | `src/alive/eyes.js`：`desktop-camera-source`（摄像头）/ `computer/capture`（屏幕） | 每种最多一帧，长边 `visionShotMaxEdge` | +1–1.5k token/帧 |
| **它自己抽屉的最后几行**（`note.md`） | `src/alive/note.js#readNote` | `aliveRecapNoteLines` 条（默认 2），每条 `aliveRecapTailChars` | 几十个字，读本地文件 |

### 它自己的记忆要先回到眼前（2026-11-12）

事实块里原来只有**别人的世界**（谁在干什么、哪些计划没收口），没有**它自己的昨天**：
它写在抽屉里的话（原话："让下次醒来的自己知道这次醒过"）只躺在硬盘上，得它自己想起来调
`alive_read_note` 才看得见 —— 而它每次醒来都是一张白纸，想不起来。于是"清单 0 条、抽屉有字
但看不见、只能 DEFER"成了稳态。

现在补三件事（**都不是新机制，是把已有的东西还给模型**）：

1. **抽屉最后 `aliveRecapNoteLines` 行进事实块**，排在外部事实**前面**（先想起自己，再看外面）。
   取事实的装配点仍是 `alive-boot.js#collectFacts`，渲染仍只在 `decide.renderStateBlock` 一处。
2. **提示词写明"清单空着也可以自己开一条"**（`loops: [{text}]`）。以前只教了怎么关（`done`），
   于是它 7 次醒来一次都没声明过。目标只能从"我记得上次到哪儿"里长出来，这一步是给它原料，
   不是给它派活。
3. **对账**：说"做完了"要对得上事实（文件在、命令成、画面变了）。代码侧只**留痕不驳回** ——
   这一轮用 `done` 关掉了条目、而**整轮**下来没有任何**它自己做的**事实（成功的 `ACTION`，
   或它自己调的睁眼）时，记一条 `DONE_NO_EVIDENCE` 事件（「拟态 → 日志」里能看见），
   但不撤销那条收口：这条可能昨天就验证过了，代码没有资格替它判断哪条算数。
   **判定在轮末，不在"决定那一刻"**（2026-11-14 修）：它常在轮初先把条目 `done` 掉、
   随后才去跑命令复核，按时刻判会把这种"先划掉后验证"的正常顺序记成缺依据 —— 假警报一多，
   这条对账就没人看了。
   **自动睁眼不算依据**（2026-11-13 修）：`wakeLookCamera/Screen` 每轮开头都会替它拍一张
   （`EYE` 带 `auto: true`），那是这一轮的**输入**；以前它也算"看过画面"，于是眼睛一开，
   `DONE_NO_EVIDENCE` 就再也没响过一次 —— 这条对账实际是关着的。

> 没有做、也不打算做：给它设"目标"、给它排待办、按关键词判断"这轮算不算没做完"。
> 那三样都会把它变成排期表，而排期表不需要拟态。

三条理由值得写下来：

1. **为什么画面要由代码取、而不是让它自己调 `desktop_camera_look`**：画面是**这一轮的输入**。
   工具在只读白名单里，但"醒了却不知道该看什么"正是它默默 DEFER 的一半原因 —— 输入不该
   依赖被唤醒者的主动性。
2. **为什么不给图也要有文字**：取不到（权限没开 / 没设备 / 模型不吃图）会写进状态块
   "屏幕没看成（PERMISSION_DENIED）"，并留 `EYE` 事件。**不许假装看过**。
3. **模型不吃图**：`alive-boot#modelSeesImages` 只认"模型设置里这个模型被标成 vision/全模态"，
   说不准就按"不会看"处理（`MODEL_NOT_VISION` 写进状态块）—— 宁可只给文字，也不要让这一轮 400。

**明确不做**（别再加回来）：云台转一圈（本仓没有任何 PTZ / UVC-XU 控制，要引外部 SDK；
一帧已足够判断"有人吗/环境变了吗"）、每轮自动开麦（"一直听着"在负向清单里）、
默认截屏（屏幕画面会周期性上传到视觉 API，必须是显式开关）。

### 它用哪个模型（`alive/settings.json#modelRoute`）
唤醒轮原来固定跟随机型设置里的默认文本模型。现在可以在「设置 → 拟态 → 生命 → 它用哪个模型」
里单独指定 —— 这是**这条命自己的脑子**，和你在对话里选哪个模型是两件事。

| 事实 | 语义 |
|---|---|
| 存哪 | `alive/settings.json#modelRoute`（`custom:<id>` / `builtin:<supplier>:<model>`；空 = 跟随默认） |
| 何时生效 | 每次唤醒现读，改完**下一轮**就生效，不用重启 |
| 选项从哪来 | Renderer 的 `listSelectableModelRoutes()`（`renderer-model-runtime.js`，**唯一一份枚举**，与「定时计划」编辑器共用；语音模型不在其中） |
| 失效怎么办 | **不静默换模型**：`resolveTurnModel` 是 strict，下一轮明确失败并记 `WAKE_ERROR`，页面把"当前不可选"写出来 |
| 看图的前提 | 这个模型要在「设置 → 模型」里被标成「全模态」；否则「醒来时先看一眼」只给文字并写明没给图（`MODEL_NOT_VISION`） |

### 设备选择与依赖自检（issue/2026-11-10 的 P0 体验项）

- **选择**：麦克风 / 摄像头都在页面上**枚举后点选**（`alive:devices` → `ffmpeg -list_devices`），
  存进 `alive/settings.json` 的 `micDevice` / `cameraDevice`；环境变量 `DIEYUN_MIC_DEVICE` /
  `DIEYUN_DESKTOP_CAMERA` 仍是**高级覆盖**（显式给了就以它为准）。
  心跳轮经 `toolScope.senses` 把选中的设备带到工具层（`tool-bridge-main` 的 `desktop_camera_look`），
  所以"页面选了 A、实际用了 B"不会发生。
- **自检**：`voice.describeVoiceCapability` 是**唯一**判定"嘴与耳能不能用"的地方
  （ffmpeg / ffplay / 转写配置 / 合成配置 / 麦克风），页面照它显示红字；
  眼睛的"两道锁"用 `capabilities.eyes`（面板开关 + `host-permissions.json` 的 `camera`/`desktopCamera`）。
  **不允许"勾着但不可用"而不说话**。
- **失败分类**：录音失败分 `DEVICE_BUSY`（被占用）/ `DEVICE_UNAVAILABLE`（找不到设备）/
  `NO_AUDIO`（没声音）/ 超时，各自一句话，不混成"没录到声音"。
- **录音当场可见**：`alive_listen` 开录前会推一条托盘/系统通知（"生命感正在听一段，最多 N 秒，
  转完立刻删音频"）—— 麦克风被占用 15 秒这件事不能只在事后的事件流里留痕。
  桌面端由 `main-entry` 注入 `notifyTray`；headless 没有就静默。

### 为什么不留缩略图

「每次睁眼保存一张可回看的缩略图」与**现实画面不落盘**直接冲突：留副本等于把摄像头变成一台
没人要求的录音笔（同一条理由见 `desktop-camera-source.js` 头注释与 `visionCameraText`）。
目前的做法是**只记事实**（`EYE` 事件：何时、哪颗摄像头、成功与否、尺寸），画面本身进视觉通道后即弃。
要回看就得显式破这条约束，那是另一次设计变更，不在本次范围。

实现位置：`src/alive/note.js`（抽屉）、`src/alive/voice.js`（说 / 听）。
两者都走 `preTool`（不是 host 工具，不进工具桥），感官关掉时**连工具都不注入**，省得它反复试。

「听」的链路：`ffmpeg` 录音 → 临时 wav → `speech-transcribe.js#transcribeWhisper` → 文字 → 删音频。
「说」的链路：`speech-synthesize.js#synthesizeSpeech` → 临时音频 → `ffplay` 播放 → 删文件。
缺件（没 ffmpeg / 没设备名 / 没语音配置 / 没 ffplay）一律返回明确错误码，**不假装听见、不假装说出**。

> 它不知道你在读抽屉。这一点是刻意的：一旦它知道有读者，写出来的东西就会变成汇报。

## 6. 执行权（`wakePower`）：它醒来能不能真的动手

**默认 `read`：心跳轮只读。** 这是原设计的承重墙，放开必须是显式选择（设置 → 拟态 → 生命 →
「它醒来能做什么」），因为这是**唯一**能让它在你不在时改动真实世界的东西。

| 档位 | 多出来的工具 | 典型场景 |
|---|---|---|
| `read`（默认） | —— | 看、听、说、读文件、检索代码库、读记忆、看计划、看内网有谁在 |
| `write` | `fs_write_file` / `fs_edit` | 整理它自己的目录、把想留下的东西落成文件 |
| `exec` | 再加 `host_exec` / `web_search` / `web_fetch` / `browser_*`（核心批）/ `computer` | 真跑命令（跑测试、跑脚本）、联网核对外面的事实、开浏览器、动键鼠 |

**它看得见什么 = 这份清单**（`aliveWakeToolNames`，`guardrails-shared.js`）：工具表不再由
`main-agent-tools` 另拼 `PLAN_RUNTIME`，而是从「档位清单 ∩ 开关表」派生 ——
`read` 档 12 个（眼睛开着 14）、`exec` 档全开 47 个（17 + 27 个浏览器核心工具 + `computer`）。
这条不变式是 2026-11-12 定下的，
因为两边各写一份会同时出两种病：清单里写了 `grep / codebase_search / memory_recall / session_recall /
plan_list / peer_list` 却没发下去（**允许了没给**，它的"读"只剩整文件读），工具表里有 `web_search`
而清单没有（**每轮撞一次 `READ_ONLY_SCOPE`**，白烧一轮）。**MCP 工具一律不注入**：名字运行期才知道
（`mcp_<server>__<tool>`），写不进按名字的清单，发下去只会每轮被拒。

**为什么出网只到 `exec` 档**：`exec` 档的 `host_exec` 本来就能出网 ——
`sandbox-policy` 在 `workspace-write` 下对「不落盘的联网命令」（`curl` 不带 `-o`、
`Invoke-WebRequest`…）判的是 allow。所以在这一档挡住 `web_*` 不构成安全边界，只是把出网挤到
另一条更差的路上：命令行拿回来的是**原始 HTML**（编码、反爬、正文提取全得模型自己扛，token 更贵），
而且绕过了 `src/gateway/web/` 里唯一的 SSRF 校验（`url-safety.assertSafeUrl`）与引擎解析。
放开这两格 = 让这一档仅有的出网走正规通道。**跨机派活**（`peer_send` / `peer_claim`）、**子 loop**（`subagent`）、
**计划**（`plan_run` / `goal_check`）仍然一律不放 —— 它们绕过 `wakeRoot` 与次数闸。
（`peer_list` 是例外：只读，能回答"那台机器在不在"，任何档都放。）

**占屏 / 键鼠（`browser_*` 核心批 + `computer`）在 `exec` 档，但要避让**：这两类会占你正在看的
屏幕、抢同一套鼠标键盘，所以每一条调用都先问一句「现在还有别的任务在跑吗」——
判据是 `getActiveAgentLoopCount() > 1`（`rust-loop-runner` 里「系统忙不忙」的唯一来源；
这一轮自己算一条，多出来就是别人）。有人在跑 → `WAKE_YIELD` 直接拒，**不排队等**：
后台轮没有等待语义，等就是把整轮挂住；让它下一轮再决定，或者把这件事记进未闭合事项。
这两类还要各自的**本机权限**（`browserAutomation` 关掉不注入 `browser_*`；
`computer` 要 `osControl`，在关卡层就是 `PERMISSION_DENIED`，与 `rpc.js` 是同一份授权）。
浏览器画面走的是内置 BrowserView（`requestAutoOpenPanel` 请 Renderer 开页签），所以它开网页时
你桌面上会真的出现那块画面 —— 这也是"有人跑任务就让路"的原因之一。

放开之后**仍然只有四道闸门**（都在 `tool-gate` 的 `read-only-scope` 关卡里；前三条的判定数据
来自 `sandbox-policy` 的两个既有入口，第四条来自 `rust-loop-runner` 的活跃轮次计数，
都不另写一份策略）：

1. **一个根目录**：`alive/settings.json#wakeWorkspace`。留空 = 它自己的抽屉
   `<userData>/alive/workspace`（**最保守**：放手让它做事 ≠ 放手让它改你的项目；
   要改项目得显式填那个目录）。任何越界写/越界 `cwd` → `WAKE_PATH_OUTSIDE`。
   这个默认值由 `alive-boot.js#wakeScopeNow` 解析（唯一来源）；**关卡只认它收到的根** ——
   收不到就 `WAKE_NO_ROOT` 直拒，**不回退 `process.cwd()`**（那等于把应用安装目录当可写根）。
   「在根下吗」与沙箱判定共用 `sandbox-policy.isUnder` 一份实现（含 Windows 大小写归一）。
   页面上这个框可以手打，也可以点「选择…」走系统目录框（复用既有的 `dialog:pick-folder`，
   与「频道 → 默认工作空间」同一个通道）；选中即写入并保存，不用再按别的按钮。
2. **每轮次数上限**：`aliveWakeWriteMaxPerWake`（6）/ `aliveWakeExecMaxPerWake`（3），
   跨调用累计、跨轮清零。超了 → `WAKE_BUDGET`。
3. **永不排队等审批**：需要用户当场同意的操作（工作区外的写、部分出网命令）在后台**直接拒**
   （`WAKE_NEEDS_APPROVAL`）；高危命令（磁盘/系统/关机/提权）由 `sandbox-policy` 判 deny
   （`WAKE_POLICY_DENIED`，另有 `exec-policy` 在更前面再拦一次）。
4. **有别的任务在跑就让路**：`browser_*` / `computer` 在 `getActiveAgentLoopCount() > 1` 时拒（`WAKE_YIELD`）。

**账必须留痕**：改动 / 命令 / 出网 / 动页面都落 `ACTION` 事件（`tool` / `target`＝文件路径、命令前 160 字、
URL / 搜索词 / 动作名 / `ok` / `errorCode`），只记目标不记内容（文件内容可能是用户的代码）。
浏览器与键鼠只记"动了页面/动了手"的那几个（`browser_navigate` / `browser_evaluate` / `computer`）——
每次 `click` 都记会把 40 行的日志刷成流水。页面在决策日志里逐条显示。

已知限度（不粉饰）：`exec` 档**不启动 `detached` 进程**，单条命令的 `timeoutMs` 会被夹到
`aliveWakeExecTimeoutSec`（默认 120s）；但**没有**做内核级资源限制，也没有 egress 白名单
（沙箱是策略层，不是内核层，见 `docs/SANDBOX.md`）——`web_*` 走 `src/gateway/web/` 的
SSRF 校验（`url-safety.assertSafeUrl`），但它筛的是「内网地址」，不是「该不该访问这个站点」。
所以这一档的正确用法是「给它一个专门的目录 + 接受它能跑命令、能上网」，而不是「把它当成可信沙箱」。

## 7. 隔离度审计（这一节回答"到底隔了什么"）

那么它和主实例到底隔了什么？先说结论：

**结论：工具面是硬隔离（白名单），数据面是软件隔离（同库不同文件），进程/记忆/额度没有隔离。**
这不是缺陷声明，是取舍声明 —— 拟态要"看着像生命"，就必须共享记忆与人格。

| 维度 | 隔离度 | 事实 |
|---|---|---|
| **工具面** | ✅ **硬（白名单，同时就是工具表）** | 清单在 `guardrails-shared.js`：`read` 档 = `fs_read_file / fs_list_dir / grep / glob / read_symbol / codebase_search / graph / lsp / memory_recall / session_recall / plan_list / peer_list`（+ 眼睛开着时的 `camera_look / desktop_camera_look`），`write` 档 + `fs_write_file / fs_edit`，`exec` 档再 + `host_exec / web_search / web_fetch` + `browser_*`（核心批 27 个，`browserAutomation` 关掉不注入）+ `computer`（要 `osControl`）。清单外一律 `READ_ONLY_SCOPE` —— 含 `peer_send / peer_claim / memory_forget / subagent / plan_run / plan_create / goal_check / ssh / worktree / host_open_url / skill_* / agents_md_propose / session_* / agent_clarify`，以及**全部 MCP 工具**（不注入）。模型看得见的 = 它调得动的（`aliveWakeToolNames` 派生，没有第二份表） |
| **感官工具** | ✅ 逐项授权 | `alive_decide / alive_note / alive_speak / alive_listen` 走 `preTool`（不是 host 工具，不进工具桥）；关掉的能力**连工具都不注入**，摄像头走 gate 的 `SENSE_DISABLED` |
| **写盘** | ✅ 默认只有一个文件 | `read` 档唯一写入点是 `alive_note` → `alive/workspace/note.md`（只追加、有上限、**模型不能指定路径**）。`write`/`exec` 档在**用户选的根目录**内可写，每轮有次数上限，逐条记 `ACTION` |
| **出网** | 🟡 `read`/`write` 档关，`exec` 档开 `web_*` + `browser_*` | 默认两档没有 `web_*` / `browser_*` / `peer_*`，碰不到网络；`exec` 档放开 `web_search` / `web_fetch`（理由见 §6：同一档的 `host_exec` 本来就能 `curl`，挡白名单只是把出网挤到没有 SSRF 校验的命令行上）与浏览器核心批（还要 `browserAutomation`、且没人正在跑任务），`peer_*` 仍不放 |
| **副作用** | ✅ 关（白名单外） | 不能删记忆、不能起子任务、不能跑计划；写盘/命令/出网各自只在对应档位里、并且留 `ACTION` 账 |
| **数据文件** | 🟡 软（同库不同文件） | `<userData>/alive/{state,events,settings}.json` 与主库物理分开，但**同一份 userData**、同一个进程、同一个 Gateway |
| **记忆** | ❌ **共享** | 唤醒轮走同一份 `prepSystemPrompt`：会注入长期记忆、AGENTS.md、技能索引。它知道你们聊过什么 —— 这是拟态的前提 |
| **会话** | 🟡 半 | 用**专属会话**（标题「生命体征（后台心跳）」），不污染你的对话线；但那次会话仍写进主库，可被 `session_recall` 检索到 |
| **决策理由** | 🟡 明文私有 | `state.intents` 不进事件流 / IPC / 页面；**但落盘是明文**，用编辑器能打开。这是"不展示"而不是"加密" |
| **模型与额度** | ❌ 共享 | 同一份 model-settings、同一个 API key，真实账单合在一起 |
| **进程 / 并发** | ❌ 无 | 同一进程、同一 event loop；用户聊天时它也可能醒来跑一轮（两个 loop 并行，抢 token 与延迟） |

三条要记住的后果：

1. **只读 ≠ 看不见**：它能读工作空间里的文件（`workspacePath` 为空时落到 Gateway 当前工作空间）。
   "隔离"在这里的准确含义是**不能改**，不是**看不到**。要连看都隔开，得给它一个空工作目录 —— 那它会变哑。
2. **白名单只能收紧不能放宽**：往 `ALIVE_READ_ONLY_TOOL_NAMES`（`guardrails-shared.js`）加一个工具名，
   等于明确表态"心跳轮可以用它"。别为了让它"能干点事"顺手加 `fs_write_file`。
   唯一一次刻意的放宽是 `web_search` / `web_fetch` 进 `exec` 档（理由见 §6：那一档的 `host_exec`
   本来就能 `curl` 出网，挡住正规通道只会换来更贵、更没护栏的路径）；这不是先例 ——
   再想加什么，先回答"它在这档已有的工具里是不是已经能做，只是做得更差"。
3. **`intent` 是本机明文**：如果哪天要真私有，得走 `DIEYUN_SECRET_KEY_FILE` 加密 —— 那是另一次设计变更。

## 8. 与主实例的边界

- 心跳轮用的是**一个专属会话**（标题固定「生命体征（后台心跳）」），不进你的对话；
- 它与你**共享记忆与模型配置**——这是拟态的前提，不是缺陷；
- 唤醒轮**默认只读**（见上一节白名单）；
- 它的判定全在 Main（`src/alive/runtime.js`），Renderer 只显示结果 —— 不在渲染层判生死、判续跑。
- **headless 目前没有装配生命感**（`src/headless/boot.js` 里没有 `bootAliveRuntime`）。
  `runtime.js` / `alive-boot.js` 是宿主无关的，复用同一份即可；但服务器上没人看着，让它每 5 分钟
  自己决定醒不醒，等于把一份无人监管的模型账单放进 systemd —— 要装配得先定"什么时段 / 什么负载
  下允许醒"，那是另一次设计变更。在那之前别在注释里假装它已经跑在两处。

## 9. 与原 spec 的其余偏离（都要记住原因）

| 项 | 偏离 | 原因 |
|---|---|---|
| 阈值公式 | 原写 `μ·(refuse_rate − 0.2)`，本实现是 `μ·(基线 − 拒绝率)` | 原 spec 的**公式与其解释方向相反**（解释是"长期不拒绝→阈值升高，更挑"）。按解释实现 |
| 漂移量纲 | 全部按**小时**归一 | 原设计按 tick 计：1 小时就能把 W 钉死在 80（评审 N2） |
| 存储 | JSON + 只追加日志，不是 SQLite | `build.files` 排除了 `better-sqlite3`，headless 只打纯 JS 闭包；为拟态引 native sqlite 要维护两套打包矩阵 |
| 验收 | 注入时钟模拟 30 天 | 原 spec 要求挂机 24h/7d；评审 M1 已改，模拟能进 CI |
| `phase_override` | 删掉 | 它与"外部只能影响相位"直接冲突（评审 B4） |

## 10. 负向清单（往回加这些 = 设计作废）

1. ❌ 给它暂停 / 恢复 / 快照 / 回滚
2. ❌ 给它预算、给它死期、给它 ETA
3. ❌ 让它对用户说话、给它名字、给它头像、给它情绪标签
4. ❌ 把 `intent` 展示到页面 / 日志 / 审计里
5. ❌ 在 Renderer 判生死、判唤醒、判续跑
6. ❌ 把 `λ / ε / W` 做成设置项（数字只有一个来源）
7. ❌ 用关键词判断"这轮算不算没做完"（未闭合项只能由模型声明）
8. ❌ 伪造一条用户消息去驱动心跳轮（一律走 `[系统]` 合成前缀）
9. ❌ 让心跳轮**默认**获得写入 / 执行能力（默认仍是 `read`；放开必须是一次显式选择，见第 6 节「执行权」）
10. ❌ 把抽屉做成双向通道（给它答复、让它知道有人在读 → 它就开始表演）
11. ❌ 让麦克风变成"一直听着"（只允许离散步长的 `alive_listen`，且音频不落盘）
12. ❌ 把"睁眼看"的画面存成缩略图 / 任何副本（要回看得先改"现实画面不落盘"这条约束）
13. ❌ 逐跳写 `TICK` 事件（288 条/天会把 `WAKE` / `DECISION` 挤出事件文件；心跳的账在 `state.json`）
14. ❌ 把用户对话的 token 记进它的疲劳（那会把"它累了"变成"你在聊天"）
15. ❌ 在 Renderer 里判"感官能不能用"（`describeVoiceCapability` / `capabilities` 是唯一来源）
16. ❌ 把 REFUSE 当"这一轮不想动"用（那是 DEFER；空手 REFUSE 不算拒绝，别用它刷拒绝率）
17. ❌ 用 `load` 拦唤醒（"你正在打字所以它不许醒"——那就不拟态了；要拦先用事件把它记清楚）
18. ❌ 把相位说成昼夜节律（相位只有 load 与 fatigue 两个输入）
19. ❌ **用 token 计量"生命"**（额度/疲劳/寿命三件事不能是同一个数，见下）
20. ❌ 把设定做成结构化人格参数（性格标签 / 五维分数 / 预置人格包）——它是**用户写的一段原文**，代码只照贴
21. ❌ 让设定进对话系统提示、或让代码替它编设定（前者改写另一份单一来源，后者是拿代码写人生）；也❌在设定页加说明文案 / 计数器 / 多字段拆分 —— 它就是一个框

### 为什么拒绝「用 token 计量生命」

`token` 现在只承担两件、彼此独立的事：**疲劳**（它自己累不累，只数唤醒轮）与**每日额度**
（你的钱，超了就不醒）。若再拿它当"寿命"，一个数就有三种含义，且会连锁出四个问题：

1. **口径分叉**：这三个量的分母、重置周期、归因都不同（疲劳跨天不清、额度按天清零、寿命永不重置）。
   仓库里所有"数字只有一个来源"的努力会在这一处破功。
2. **把活着绑到基础设施上**：额度用完、断网、供应商下线、模型改名都会变成"它死了" ——
   那是把**钱包和网络的偶然**解释成**命运**。
3. **死期会制造表演**：`intent` 之所以私有（见第 3 节），是因为"理由一旦公开，它就开始为观众活"。
   倒计时是同一类压力，且更强：它会写遗言、煽情、抢戏剧性动作。
4. **护栏变健康条**：1 亿/天 本来回答"该不该让它醒"；升格成"命"之后，你会开始为了"它还活着"
   加预算 —— 成本控制立刻政治化。

如果将来确实想要一条"生命的形状"，用**生平**而不是**寿命**：它收口过多少件事
（`DECISION.done` 的累积）、声明过多少条、抽屉里留下多少行、看过多少次空房间。
这些是不可逆的累积，但不是倒计时，不会催它表演。

## 12. 已知限度（不粉饰）

- **它是拟态，不是生命**。没有损耗、不会死、记忆不会失去 → 它无法产生"真正的取舍"。
  原 spec §14 Q5 那句"值不值得做"在这里的答案是：**作为可观测的拟态值得，作为生命验证不值得**。
- **`ε` 与随机性不是"自发"**。它保证"没有输入时仍有差异"，但不构成"内部动机"。
- **信息差是设计出来的，不是长出来的**：`intent` 私有 + 记忆不外显，这一点能立住；
  但"它有你没有的经历"这件事本实现不提供 —— 它没有经历，只有状态与共享记忆。
- **未闭合项的质量取决于模型**。模型若从不声明，张力只由静默上升驱动，行为会显得单调。
- **设定是「一次写死」的**：`setup` 只能由你在设置页改，它没有工具去改写自己的设定
  （能改就不是设定，是即时可变的人设）。它想"长出自己的方向"，只能写进 `loops` 与抽屉。
- **开关是运维意图，不是生命体征**。关久了再打开，它不会"记得自己停过"（`dtH` 上限 24h，不会一次结算一周）。
- **心跳本身不花钱**：没越线的那一跳只做算术（漂移 / 相位 / 阈值），**不调模型**；
  只有真要醒时才跑一轮。所以"心跳很贵"通常是误读 —— 页面上 `totalTokens` 是**唤醒轮**的累计，
  而它曾经被误算成"每跳都跑一轮"（issue/2026-11-10 的附带观察，已纠正）。
- **页面读数是轮询来的**（页签可见时 5s 一次）：它不是实时仪表盘，只是"别让你看到五秒前的旧数"
  这件事的下限。真要实时，得让 Main 推事件，那是又一次设计变更。
