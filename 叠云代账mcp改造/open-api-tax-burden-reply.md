## 1. 七条口径确认（逐条）

### 1.1 税负率公式

`应纳增值税 ÷ 不含税销售额 × 100%`。

- 分母 = 期间内销项发票「金额」合计（不含税销售额），**不含**简易计税销售额、免税销售额（系统当前无这两类数据，接口保留 `simpleTaxSales` / `exemptSales` 字段，无数据时为 null）。
- 单月与期间累计口径不同：单月 = 当月应纳 ÷ 当月销售额；期间累计 = 期间应纳合计 ÷ 期间销售额合计。
- 依据：`invoice.service.ts` `insertTaxBurdenRecord()`（写入 `sf.税负认证明细` 的「累计税负」= 应纳税额年 ÷ 营业收入年）。

### 1.2 进项范围

**仅「已勾选」**（含勾选入库时置为已勾选的票）。

- 「无需勾选」**不计入**：`addInvoiceToYtd()` 首行 `if (isNoNeedCheckStatus(line.checkStatus)) return;`。
- 抵扣选项为「不抵扣」的票**不计入**：`isNonDeductOption()`。
- 属期早于该客户最早销项属期的进项**不计入**（防止建账前票参与）。
- 因此需求 2.1 节「已勾选/无需勾选且发票状态正常」的表述与系统实际不符：**系统只算已勾选**。这也是 Agent 自算（含未勾选）比界面多 33,961.47 的直接原因。

### 1.3 红冲处理

**按净额**。

- 红字发票以负数行本身参与合计，跨月红冲计入红字发票的「税款所属期」（无所属期时按开票月）。
- 已全额红冲的原票**不剔除**（原票 + 红字票净额为 0），避免与「剔除原票」重复扣减。
- 部分红冲同理，按净额。

### 1.4 作废票

- 进项：作废票不进勾选池（`findPendingSelectPurchases()` 排除「已作废」），不会计入。
- 销项：**当前未按发票状态过滤**（`addInvoiceToYtd()` 不看 `invoice_status`）。觅柔无作废销项，故不影响本客户数字。若要求销项也排除作废，需新增过滤，会改变历史期间数字，**请确认是否要改**。

### 1.5 未完结当期

- `isSettled` 判定：该期已写入 `sf.税负认证明细`，**或** 所属期早于当前自然月。
- `total` 默认只累加 `isSettled=true` 的期间（`includeUnsettled=false`）；`includeUnsettled=true` 时全计。
- 实测：`2026-01~2026-10` 默认返回 9 个已完结月，10 月已开票的 277.9 万销售额不计入累计。

### 1.6 固定资产双倍抵扣

界面指标名是「**固定资产累计税负**」，不是"双倍抵扣后税负"：

```
固定资产累计税负 = (应纳增值税 + 固定资产类进项税额) ÷ 不含税销售额 × 100%
调整额 = 期间内「分类=固定资产」的进项税额合计
```

- 调整额作用在**分子**，使税负率**上升**（0.9526% → 0.9781%），不是下降。
- 觅柔 2026-01~09 调整额 = **3,969.02**（2 张固定资产票：2026-05 3,566.37 + 2026-07 402.65），不是需求文档推测的 4,264.39（详见 3.2）。

### 1.7 留抵

- 期初留抵**冲减**本期应纳：`应纳 = max(0, 销项 − 进项 + 进项转出 − 期初留抵)`。
- 负数结转下期留抵：`期末留抵 = max(0, −(销项 − 进项 + 转出 − 期初留抵)) − 免抵退应退税额`。
- 留抵转出、免抵退应退税额来自客户留抵转出记录（`tax_cert_carry_forward`，人工录入），发票里没有。
- 觅柔 2026-06 有进项税转出 2,666.30。

## 2. `caliberNote` 文案（可直接展示给会计）

> 进项仅计勾选状态为「已勾选」的发票，勾选状态「无需勾选」与抵扣选项「不抵扣」的发票不计入；销项按税款所属期（无所属期时按开票月）计入，红字发票以负数净额参与；进项税额转出、免抵退应退税额取客户留抵转出记录；应纳增值税＝销项税额−可抵扣进项税额＋进项税额转出−上期留抵税额（负数结转下期留抵）；税负率＝应纳增值税÷不含税销售额×100%；「固定资产累计税负」＝（应纳增值税＋固定资产类进项税额）÷不含税销售额×100%。

接口每次返回都带 `caliberNote` 原文，Agent 可直接透出。

## 3. 需求文档勘误（4 处，请确认）

### 3.1 `inputTax` 与 `inputTaxTransferredOut` 拆分错误

| 字段 | 需求文档 | 系统实际 |
|---|---|---|
| inputTax | 1,876,689.16 | **1,879,355.46** |
| inputTaxTransferredOut | 0.00 | **2,666.30**（2026-06 进项转出） |

两者相减正好等于文档值，`payable` 148,395.87 一致，所以总额没错，但**字段语义必须按实际返回**，否则 Agent 拆解税额时会错。依据：`sf.税负认证明细` ID=2543 的「进项税额年 / 进项税额转出年」。

### 3.2 固定资产调整额

| 项 | 需求文档 | 系统实际 |
|---|---|---|
| 调整额 | 4,264.39 | **3,969.02** |
| 固定资产累计税负 | 0.98% | **0.9781%**（界面两位小数显示为 0.98%） |
| 对应应纳税额 | 152,660.26 | 152,364.89 |

文档的 4,264.39 是用界面显示值 0.98% 反推的（0.98% × 15,577,577.76 = 152,660.26），**用两位小数反推必然对不上**。请以接口 `metrics.fixedAssetDoubleDeductionAmount` 为准。

### 3.3 2025 全年应纳税额差 6.28

| 项 | 需求文档 | 当前库重算 |
|---|---|---|
| 2025 销售额 | 12,323,341.95 | 12,323,341.95 ✓ |
| 2025 应纳税额 | 103,670.19 | **103,676.47** |
| 税负率 | 0.84% | 0.8413% |

- 该客户在 `sf.税负认证明细` 现存仅 2026-09 一条（ID 2543），历史月记录已被覆盖/撤销后重写，无法回溯当时界面值。
- 差额 6.28 集中在 2025 年某月，推测为验收数字取自当时界面，之后 2025 年发票有补录或调整。
- **请确认验收基准**：按「当前库重算」（103,676.47）还是「历史界面截图」（103,670.19）。若必须对齐后者，请指出具体差异月份。
